# Visual design

## Composition and hierarchy

Start with one task and the information needed to decide what to do. Put the task name, current context and likely next action in a predictable reading order. Assign one dominant action per decision area. Give destructive actions explicit labels and reserve strong destructive emphasis for the point of commitment. In a project list, give the project name and status precedence over metadata. Use weight and alignment before increasing every heading size or turning each region into a card.

Use proximity to show relationships. Keep a label, input and feedback closer together than adjacent fields. Align groups to shared edges and mixed text sizes to a common baseline where practical. Give outer sections greater separation than their contents. Start with enough space to read and navigate, then tighten repeated rows for workflows that benefit from scanning. Limit prose width and let tables or canvases use available space.

## Type, color and surfaces

Use a small set of named text roles with size, weight and line height together. Start with platform-appropriate UI fonts and verify fallback glyphs. Use tabular figures when comparing numeric columns and align comparable values consistently. Test realistic long names, translated labels and larger text. Keep headings meaningful for navigation even when visual emphasis places an action or value first.

Choose semantic foreground, border and surface pairs. Reserve accent for current position, selection or an action needing attention. Give status a second cue such as a label or icon. Check foregrounds against their actual composited backgrounds across themes and states. Tune muted text while preserving contrast for information users need. Keep gradients and illustration away from dense reading or editing surfaces unless contrast remains predictable.

Give depth a purpose. Use spacing or a surface change for grouping, a divider for an ambiguous boundary, and elevation for transient layers. Pick a consistent icon family and optical size. Keep icon-only actions familiar and give them accessible names and visible help on focus and hover. A small glyph can sit inside a larger padded hit region.

## Desktop finish

Check default, hover, pressed, focused, selected, disabled and busy states in context. Distinguish selection from keyboard focus. Use motion to explain a change of position or state, preserve continuity on interception, and provide prompt reduced-motion feedback. Preserve stable layout while data arrives. Resize through minimum, typical and wide windows. Favor wrapping or a purposeful layout switch over shrinking text or clipping required actions.

Review two passes. First, scan a full window for competing emphasis and unclear grouping. Then inspect a dense row and an overlay for baseline, padding, icon alignment and state contrast. Use original content and art that serve the task.

Sources: [Refactoring UI](https://www.refactoringui.com/), [GNOME HIG](https://developer.gnome.org/hig/), [Windows design guidelines](https://learn.microsoft.com/en-us/windows/apps/design/guidelines-overview).
