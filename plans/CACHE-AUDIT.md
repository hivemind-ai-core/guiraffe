# GUIraffe cache audit

Base: `1e9d2367a3541a8eb05cc8588de46c63f97972a0` on `perf-cache-audit`. Static source review against [spec/23](../spec/23-production-readiness.md). Test names identify existing source evidence. No builds, test runs or runtime measurements.

## Findings in risk order

1. **High · Sheet queues hold an arbitrary number of edits and potentially complete calculated maps.** [Recalculator::new and submit](../crates/sheet/src/recalc.rs#L43) use two unlimited channels. Slow or block a custom formula compiler and send batches faster than it applies them. Independently, submit a new edit after each completed calculation while leaving the output unread. Every publication clones the value map ([line 63](../crates/sheet/src/recalc.rs#L63)), which can contain 100k formula results at spec scale. Revision cancellation skips obsolete calculations but every input is still applied, and previously published results remain queued. Drain or drop the session.
2. **High · Notification overflow grows independently of the visible limit.** Send unique persistent notifications while the visible slots stay occupied. [ToastQueue::push](../crates/overlays/src/toast.rs#L97) and [StackModel::push](../crates/windows/src/notify/model.rs#L241) append overflow. The window service also owns callbacks for pending cards. Clear, dismiss or let cards promote and expire to release payloads. These are independent queues.
3. **High · Code decoration styles survive deletion of every layer that used them.** Change an annotation's or blame label's style on every revision, removing its previous layer each time. [DecorationSet::intern_style](../crates/code/src/decorations.rs#L233) appends to a vector and map and reserves stable IDs. [Layer deletion](../crates/code/src/decorations.rs#L275) never removes styles. The representational limit is up to 2^32 IDs with variable-size payloads. Replacement of the entire set releases it.
4. **High · Chat's 64-row limit excludes pinned views.** Keep visiting rows covered by a window selection, or append messages marked streaming and scroll across them. [Eviction moves qualifying rows to pins](../crates/chat/src/history.rs#L56) and the [predicate](../crates/chat/src/message.rs#L122) includes streaming, an open menu and selection in either body or reasoning. The weak map does not own the entity, but the corresponding history row does. At 100k history rows the conservative worst case is 100k mounted rows including recent and pinned, with their Markdown, tool entities and subscriptions. Select-all should be evaluated against the window's participant projection, including already mounted selected rows. The 100k upper bound follows from history size and is not a claim that one select-all immediately mounts every cold row. Pins are revisited on new row admission, so clearing selection without another admission can leave mounted rows. Long-lived accumulating history allows the count to grow past the spec workload.
5. **Medium · Tray event delivery has no backpressure.** Feed raw scroll/activation events to a live sink while the UI executor has not polled its reader. [Tray::install channel creation](../crates/tray/src/service.rs#L241) accepts the backlog until delivery or receiver teardown. The second textual unbounded-channel hit in SNI is a test.
6. **Medium · App/window registries retain historical names.** Mount, resize and close splitters under unique persistence keys. [MemoryPersist::save](../crates/layout/src/splitter.rs#L317) has no per-key deletion. Open and persist windows with distinct saved layout keys and close them. [WindowManager capture](../crates/windows/src/manager.rs#L325) inserts records and [close](../crates/windows/src/manager.rs#L392) removes live entries only. On one window, register context builders with fresh names. [OverlayHost::register_context](../crates/overlays/src/host.rs#L419) replaces matching names and provides no unregister operation, so captured objects can also survive to teardown.
7. **Medium · Animation and frame scratch can retain a workload peak.** [PresenceList::sync](../crates/motion/src/layout.rs#L271) rebuilds storage from current and leaving keys, and [frame](../crates/motion/src/layout.rs#L326) drops settled entries. Replace a keyed list repeatedly within an exit duration and keep its parent mounted. Peak entries scale with churn during that interval and allocation can survive the peak. [Upstream Frame::clear](../vendor/gpui-pre/src/window.rs#L1123) clears the state table and access log without shrinking them. Present successively larger sets of unique keyed elements then return to a small view to grow retained capacity. The [tab-stop order](../PRODUCTION.md#shared-gpui-repaint-storage) has the same historical-peak property on both backends and is documented as such.
8. **Medium · Weak observer records can outlive closed viewers.** Repeatedly create and drop a Code trace dependent without driving the notification path. [Trace registration pushes](../crates/code/src/surface.rs#L1885) and [notification prunes](../crates/code/src/surface.rs#L293). Dead records and their weak ownership accumulate between sweeps. Similarly, repeated mock tray updates append to its [test backend recording](../crates/tray/src/backend.rs#L140) until the mock is dropped.

9. **Medium · Superseded Store timers retain queued actions until their deadlines.** Repeatedly schedule a large action under the same debounce key with a long delay. [Store::schedule_later](../crates/state/src/store.rs#L362) captures the action in each detached future before the ticket check. The latest ticket controls execution only. Each future releases its action when it wakes and exits. No bound test or production documentation identified.
10. **Medium · SNI update dispatch can accumulate tasks despite the staging slot.** Call update repeatedly before the background executor services it. [SniBackend::update](../crates/tray/src/sni.rs#L218) overwrites one pending snapshot but detaches a new task each time. If flush tasks reach a slow platform update, each in-flight flush can also own the snapshot it took. Tasks release on completion. No bound test or production documentation identified.

The added sections cover Sheet, Tray, Components, motion and tree collapse, and vendored patches. A documented entry count is distinct from a byte cap and tests of normal replacement are distinct from tests of adversarial growth.
